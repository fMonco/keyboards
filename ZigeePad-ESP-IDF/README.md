# Micropad 3×3 — XIAO ESP32-C6

ESP-IDF 6.1, Espressif Zigbee SDK 2.0.4. Zigbee End Device, модель
`Micropad`, производитель `Monco`, endpoint 1. Радио использует встроенную
антенну XIAO. Это самостоятельная реализация, не копия прошивки из гайда.

## Краткая карта прошивки

| Что менять / смотреть | Где | Сейчас |
|---|---|---|
| Столбцы | `main/board_pins.h`, `MATRIX_COL*_GPIO` | D7/D8/D9 = GPIO17/19/20 |
| Строки и пробуждение | `main/main.c`: `rows`, `matrix_init`, `enter_sleep`; `main/rtc_wake_stub_micropad.c`: `wake_rows`, hold-маска | D0/D1/D2 = GPIO0/1/2; переносить согласованно |
| Single/double/hold | `main/buttons.h`; алгоритм в `buttons.c` | Debounce 25 мс, double 350 мс, hold 700 мс |
| Электрическое сканирование | `main/matrix_scan.h`, `matrix_scan_cycle` | Паузы 150/100 мкс, защита от LOW на отпущенной строке |
| Первое нажатие после сна | `main/rtc_wake_stub_micropad.c`, `micropad_wake_stub` | Ранний захват; 5 × 5 мс плюс сканирование |
| Время сна/бодрствования | Начало `main/main.c`: `IDLE_MS` и соседние константы | 500 мс idle; 1 с после READY; 250 мс после TX |
| Исключение для настройки | `SETUP_AWAKE_MS` | 20 с после READY при RESET/питании/первом join |
| Если нет сети | `RECONNECT_WINDOW_MS`, `JOIN_WINDOW_MS` | 25 с после клавиши, 120 с после RESET/питания |
| Повторы отправки | `TX_TIMEOUT_MS`, `RETRY_MS`, `attempts < 3` в `app_main` | Таймаут 15 с, пауза 2 с, до 3 попыток |
| Очередь | `QUEUE_SIZE`, `pending` в `main/main.c` | 32 события в RTC RAM; отключение питания очищает |
| Zigbee и родитель | `zigbee_task` в `main/main.c` | End Device; timeout 2048 мин; keep_alive 1000 мс только при работе стека |
| Имя устройства | `create_device` в `main/main.c` | `Monco` / `Micropad`; первый байт каждой строки — длина |
| События Home Assistant | `send_event` и `zigbee2mqtt/micropad.mjs` | 1…9 press, 11…19 double, 21…29 hold |
| USB-монитор | `tools/monitor.ps1` / `tools/monitor.py` | COM3, 115200, переподключение после сна |
| Светодиод успешной отправки | `main/main.c`: `STATUS_LED_GPIO`, `LED_BLINK_MS`, `status_led_update` | GPIO15; 80 мс свет → 80 мс пауза → свет до сна |
| SDK и сборка | `main/idf_component.yml`, `sdkconfig.defaults`, `partitions.csv` | Zigbee SDK 2.0.4, сборка на IDF 6.1; приложение с 0x20000 |

Обычный цикл: **кнопка → ранний захват → загрузка и Zigbee → распознавание
жеста → очередь → отправка и подтверждение → deep sleep**.
Сканирование и восстановление Zigbee идут параллельно.

Сон разрешён, когда завершены жесты, отпущены кнопки и BOOT, нет ошибки
матрицы и ожидаемого подтверждения TX; дополнительно должны пройти интервалы
idle/READY/TX из таблицы. Они идут частично одновременно. В нормальном случае
очередь уже пуста. При сбоях сон возможен с сохранённой очередью после
исчерпания попыток/окна подключения. Перед реальным сном есть ещё 250 мс
для USB-лога с проверкой новых нажатий. Таймерных пробуждений нет.

Изменение `sdkconfig.defaults` не обязательно переопределит существующий
`sdkconfig`: текущие настройки сборки проверяй через `idf.py menuconfig`.

## Подключение и тест пинцетом

| Строка / столбец | C1: D7 (GPIO17) | C2: D8 (GPIO19) | C3: D9 (GPIO20) |
|---|---|---|---|
| R1: D0 (GPIO0) | Кнопка 1 | Кнопка 2 | Кнопка 3 |
| R2: D1 (GPIO1) | Кнопка 4 | Кнопка 5 | Кнопка 6 |
| R3: D2 (GPIO2) | Кнопка 7 | Кнопка 8 | Кнопка 9 |

Пинцетом замыкай **одну пару контактов из таблицы**. Например, D0–D7 —
кнопка 1; D1–D8 — кнопка 5; D2–D9 — кнопка 9. Для такого теста диоды и
внешние резисторы не нужны. Не замыкай контакты питания 3V3, 5V или BAT.
Замыкание строки на GND не соответствует отдельной кнопке матрицы.

Неактивные столбцы — входы с внутренней подтяжкой, выбранный столбец — выход LOW.
Строки используют внутренние pull-up. Для окончательной матрицы ставь
по одному 1N4148 на кнопку: **строка → анод → катод (полоска) → кнопка → столбец**.
Без диодов одновременные замыкания могут давать ложные дополнительные клавиши.

При сканировании после освобождения столбцов выдерживаются 150 мкс,
после выбора столбца — 100 мкс. Если строка остаётся LOW при всех отпущенных
столбцах, её чтение считается недостоверным: события этой строки подавляются,
в логе появляется `MATRIX: LOW with all columns released`. Это диагностика
уровня на входе, а не заключение о причине (проводка, помехи или настройка GPIO).
Пока такая ошибка присутствует, сон блокируется для предотвращения цикла
немедленных пробуждений. Диагностика одинаковая в wake stub и обычном сканере.

## События

| Жест | Условие | presentValue | action Zigbee2MQTT |
|---|---|---|---|
| Single | Одно нажатие и отпускание | 1…9 | button_N_press |
| Double | Второе нажатие не позднее 350 мс после отпускания первого | 11…19 | button_N_double |
| Hold | Удержание 700 мс | 21…29 | button_N_hold |

Дребезг фильтруется 25 мс. Single приходит после истечения окна double.
Hold отправляется один раз, отпускание после него не создаёт single.
Первый короткий клик и затем длинное второе нажатие дают single + hold.
Каждая клавиша обрабатывается независимо. На проводе используется стандартный
Report Attributes кластера Multistate Input (0x0012), атрибут PresentValue
(0x0055), тип uint16. Отправка — напрямую координатору 0x0000, endpoint 1;
binding и configureReporting для событий не требуются.

## Zigbee2MQTT

1. Скопируй `zigbee2mqtt/micropad.mjs` в свой каталог `external_converters`.
   Файл содержит только JavaScript, без строк с тройными обратными кавычками.
2. Перезапусти Zigbee2MQTT и включи Permit join.
3. Перезапусти Micropad кнопкой RESET или питанием. Для первой настройки
   держи Permit join открытым; устройство пытается подключиться до 120 секунд.
4. После завершения interview замкни D0–D7 примерно на 100–200 мс и отпусти.
   Ожидается `button_1_press`. Затем проверь double и hold.

Имена событий совпадают с конвертером из переписки. Приложенный конвертер
принимает только attributeReport: чтение атрибута при interview не должно
повторять прошлое нажатие. Не добавляй автоматический периодический reporting
этого атрибута: он используется как событие, а не как постоянное состояние.

Для сброса сопряжения: нажми RESET, затем держи встроенную BOOT 5 секунд.
Также доступны сочетания кнопок матрицы:
- **1+3** удерживать 3 секунды и отпустить все кнопки — перезагрузка с сохранением сопряжения.
- **1+9** удерживать 5 секунд и отпустить все кнопки — сброс данных Zigbee
  и очереди событий, перезапуск и новое сопряжение. Заранее включи Permit join
  в Zigbee2MQTT. Прошивка и внешний конвертер сохраняются.

Держать нужно ровно указанную пару. Действие выполняется после отпускания,
чтобы удерживаемые кнопки не вызывали повторные перезагрузки. С момента
обнаружения пары события клавиш подавляются до отпускания; события,
отправленные до обнаружения пары, отменить невозможно. Если отпустить раньше
порога, сброса не будет. Интервалы задаются в `main/chords.h`.
Во время удержания 1+3 встроенный LED мигает с периодом 500 мс, при 1+9 —
200 мс. После достижения порога горит постоянно: можно отпускать кнопки.
Эта индикация имеет приоритет над индикацией отправки Zigbee.

BOOT сама по себе не является источником пробуждения из deep sleep.
После сброса перезапуск и новое сопряжение происходят автоматически.

## Сон и доставка

Встроенный LED выключен после старта. При подтверждённой передаче Zigbee он
вспыхивает на 80 мс, гаснет на 80 мс, затем горит до deep sleep. Каждая новая
успешная передача повторяет блинк; ошибка отправки его не запускает. Если
ранее уже была успешная передача, LED продолжает гореть до сна даже при
ошибке следующей. Это подтверждение передачи, а не выполнения автоматизации
Home Assistant. Перед реальным сном LED выключается с удержанием GPIO15
в HIGH. Индикация не добавляет задержку к существующим условиям сна.

Батарейный режим: периодические пробуждения отключены. После пробуждения
клавишей сон разрешается через 500 мс бездействия, когда клавиши отпущены,
жесты завершены и отправки подтверждены. Дополнительно выдерживаются минимум
1 секунда после восстановления Zigbee и 250 мс после результата отправки.
Перед сном USB-логу даётся 250 мс для вывода последней строки.
После RESET/включения питания и нового сопряжения оставлено 20 секунд
для настройки и interview — это исключение для обслуживания. Перед сном все
столбцы удерживаются в LOW; любой LOW на GPIO0/1/2 будит через EXT1.
Перед сном строки переключаются на RTC GPIO с отдельными внутренними
подтяжками вверх: обычных digital GPIO pull-up для EXT1 на C6 недостаточно.
После переключения ещё раз проверяется, что строки HIGH. Ранний wake stub
возвращает строки на digital GPIO перед сканированием матрицы.

Ранний wake stub сканирует матрицу до загрузчика и запоминает кнопку,
стабильную 25 мс. Это позволяет обработать нажатие, отпущенное во время
загрузки. Очень короткие касания, дребезг пинцета и переходы, полностью
попавшие в промежуток загрузки, могут быть пропущены: проверяй сначала
нажатиями 100–200 мс. Hold отсчитывается основным приложением и при
пробуждении имеет небольшую дополнительную задержку загрузки.

Из deep sleep устройство будит только матрица, таймер отключён. RESET и
подача питания также запускают плату. Запрашивается End Device timeout
2048 минут (около 34 часов), но родитель может использовать другой срок.
После долгого отсутствия родитель может удалить запись о ребёнке; тогда
при нажатии потребуется восстановление Zigbee-связи, что увеличит задержку.
Проверка возврата после такого удаления требует отдельного длительного теста.

До 32 неотправленных событий хранятся в RTC RAM. При недоступности сети
устройство не бодрствует бесконечно: окно восстановления после клавиши —
25 секунд, после RESET/питания — 120 секунд. Начатая отправка может продлить
ожидание до своего таймаута. Следующая попытка — при следующем нажатии,
автоматических попыток во сне нет. При переполнении новые события
отбрасываются с сообщением в логе; отключение питания очищает очередь.
После трёх неудачных отправок событие сохраняется до следующего пробуждения.
При потере подтверждения повторная доставка может дать дубликат: данный
протокол не содержит идентификатора события для гарантии exactly-once.

## Сборка и прошивка

В терминале ESP-IDF 6.1:

```powershell
idf.py build
idf.py -p COM3 flash monitor
```

Перед прошивкой закрой другой Serial Monitor, занявший COM3.
Для монитора с автоматическим переподключением после сна запусти
`powershell -ExecutionPolicy Bypass -File tools/monitor.ps1` или выбери в
VS Code **Terminal → Run Task → Micropad: Serial Monitor (auto reconnect)**.
Этот монитор не сбрасывает плату при открытии. Если она уже спит, замкни
пару строки и столбца или нажми RESET. Обычный пустой терминал без
запущенного монитора не получает данные COM-порта.
`build/micropad.bin` — только приложение, адрес **0x20000**.
Для первой прошивки используй `idf.py flash`: он также записывает загрузчик
и таблицу разделов. Не записывай файл приложения по адресу 0x0.
USB-порт может исчезнуть при deep sleep и вернуться при пробуждении.
Каждые 5 секунд бодрствования печатается `STATE: AWAKE`, состояние Zigbee,
время бездействия, нажатые клавиши и очередь. Перед сном —
`STATE: ENTERING DEEP SLEEP`; после пробуждения — `STATE: AWAKE` с причиной
`KEY` или `POWER/RESET`. Во сне процессор не печатает сообщения.
Для входа в загрузчик при проблемах: держи BOOT, нажми RESET, отпусти BOOT.

## Проверки

Сборка проверяется под ESP-IDF 6.1 для ESP32-C6. Поведение на GPIO,
сопряжение с конкретным координатором, получение событий и ток сна требуют
проверки на плате. Успешная компиляция не заменяет эти проверки.

`tests/test_buttons.py` исполняет **реальный C-код** через DLL на Windows.
Например, с TinyCC для Windows x64:

```powershell
tcc -shared '-Wl,-export-all-symbols' main/buttons.c -o build/buttons.dll
python tests/test_buttons.py build/buttons.dll
node tests/test_converter.mjs
```

Проверяются дребезг, single/double/hold, граничные интервалы, независимые
кнопки, переполнение счётчика времени и отпускание wake-кнопки до старта приложения.

Распиновка: https://wiki.seeedstudio.com/xiao_esp32c6_getting_started/
Сон: https://docs.espressif.com/projects/esp-idf/en/stable/esp32c6/api-reference/system/sleep_modes.html
